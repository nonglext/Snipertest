# Sniper — тестовая версия

Локально: `ADMINS="boss:пароль123,helper:пароль456" node server.js` → http://localhost:3000

## Render
Build Command: `npm install`. Start Command: `node server.js`.
Environment:
- `PAYMENT_MODE` = `test`
- `ADMINS` = `ник1:пароль1,ник2:пароль2` (2 админа; ник 3-20 символов, пароль от 8). Эти ники в обычной регистрации заняты.
- `DATABASE_URL` = ссылка на Postgres (Render → твоя база → Connections → **Internal Database URL**, если сайт и база в одном регионе, иначе External). Тогда всё хранится в Postgres и не пропадает при перезапуске. Таблица `app_state` создаётся сама, при первом запуске данные из `db.json` переносятся.
- (если без Postgres) `DATA_DIR` = `/var/data` + Disk с этим путём.
- `PGSSL` = `off` только если Postgres без SSL (локально).

## Админка
`/admin.html`. Вход логином и паролем из ADMINS. Вкладки: Сток (добавление пачкой, цена, удаление), Заказы, Поддержка.
Формат добавления: `ник | данные`, несколько строк данных в одной записи через `;;`.
Админ-аккаунты создаются при старте; смена пароля = смена значения в ADMINS.

ВАЖНО: сток живёт в базе, а не в stock.json. Без `DATABASE_URL` (или постоянного диска) всё, что добавлено через админку, пропадает при перезапуске Render.

## Крипта
Вся выдача идёт через `markPaid(order)` в server.js. Сейчас её вызывает фейк-кнопка, потом будет webhook шлюза.

## Оплата и заказы
Клиент жмёт «оплатил» → заказ «на проверке» → админ в `/admin.html` → «Заказы» подтверждает («Деньги пришли — выдать») или отклоняет. Данные выдаются только после подтверждения.

## WebSocket
Эндпоинт `/ws` (без зависимостей, свой RFC 6455 в server.js). Обновления тикетов, заказов, каталога и заявок для админа приходят сразу. Если сокет оборвался, клиент переподключается сам, а пока связи нет, работает запасной опрос. Render WebSocket поддерживает без настроек.

## Поддержка
Закрытый тикет: писать нельзя ни клиенту, ни админу (сервер вернёт 409). Антиспам: не чаще раза в 1,5 с, не больше 5 сообщений за 30 с, одинаковый текст подряд не дублируется.
